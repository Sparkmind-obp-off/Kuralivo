# KURALIVO — AI Content Pipeline

## Pipeline overview
1. Intake brief.
2. Verify product and audience context.
3. Build evidence pack.
4. Create creative hypotheses.
5. Generate content drafts.
6. Review claims, assets, and disclosures.
7. Human approval.
8. Export.
9. Manual publish through the separate account.
10. Record real performance.
11. Decide the next test.

## Stage 1: intake
Capture product/category, target audience, audience problem, channel, objective, language, format, CTA, content constraints, and what is not known.

## Stage 2: evidence pack
Prefer official product listings, merchant documentation, product manuals, and authoritative sources. Record URL, title, date checked, supported facts, limitations, asset permission, and contradictions. Do not treat search snippets or model memory as final verification.

## Stage 3: creative hypotheses
Each concept should contain:
- target viewer and specific problem;
- proposed angle;
- hook;
- evidence supporting the core claim;
- content format;
- CTA;
- likely objection or limitation;
- compliance risk;
- what the experiment is meant to learn.

## Stage 4: generation
Generate distinct assets in sections: hooks, script, storyboard, visual direction, voice-over, on-screen text, caption, CTA, disclosures, and source notes. Keep the output editable and avoid generating unsupported facts.

## Stage 5: review gate
Check:
- factual accuracy and source support;
- exact product depiction and listing consistency;
- no fabricated hands-on use, unboxing, review, testimonial, or results;
- permitted use of footage, images, music, logos, fonts, voices, and likenesses;
- current AI-generated-content disclosure rules;
- clear affiliate disclosure when relevant;
- channel and program permit the format and link placement;
- price, discount, stock, and commission are current and sourced if mentioned;
- final render matches the approved script and assets.

## Stage 6: export package
A content package should include:
- selected angle and intended audience;
- final script with timing;
- shot list/storyboard;
- visual asset instructions and asset manifest;
- on-screen text;
- voice-over draft;
- caption and CTA;
- source notes;
- required disclosures;
- final review checklist;
- version and export date.

## Stage 7: publishing and learning
Publish manually only when permitted. Record post URL, date/time, platform, format, and metrics as reported by the platform or affiliate partner. Keep hypotheses separate from observations. Do not equate views with purchases or reported commission with payout.

## Failure paths
- No evidence → save as Researching.
- Conflicting evidence → note conflict and avoid the claim.
- Rights unclear → replace asset or pause.
- Required disclosure unknown → verify policy before publication.
- Model output malformed → retry boundedly or edit manually.
- Platform integration unavailable → manual export; label integration status honestly.
