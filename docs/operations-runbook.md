# KURALIVO — Operations Runbook

## Daily operation
1. Choose one project and a specific audience problem.
2. Verify product details and affiliate eligibility as relevant.
3. Update the evidence pack with sources and dates.
4. Generate a small set of distinct concepts.
5. Select the clearest evidence-supported concept, not merely the strongest hook.
6. Generate script, storyboard, visual directions, caption, CTA, and disclosure notes.
7. Review facts, product accuracy, asset rights, and current policy requirements.
8. Render and inspect the final video against the approved plan.
9. Publish manually through the separate authorized account, only when permitted.
10. Record post URL/date and actual source metrics when available.

## Weekly review
- Count completed, approved, and published assets separately.
- Review production time and correction rate.
- Compare like-for-like metrics.
- Note complaints, removals, broken links, and policy concerns.
- Pick one next experiment.
- Keep spending within approved limits.

## Troubleshooting
- AI provider unavailable: use saved templates/manual drafting.
- Unsupported output: return to evidence pack, edit or reject.
- Asset rights unclear: replace the asset or pause.
- No affiliate access: publish only permitted non-shoppable content; do not imply commissions.
- No metrics: record publication only and leave performance blank.
- Broken destination: stop promoting the link until verified.
- Unexpected spend: stop optional usage where safe, inspect provider billing, and avoid blind retries.

## Release checklist
Core flow tested; status transitions correct; no secrets in source control/logs; empty/error/loading states reviewed; source/disclosure checklist available; manual fallback works; documentation matches actual implementation.

## Truthful status labels
Available = tested. Beta = usable but limited. Planned = future work. Not connected = no verified active connection. A Git commit is not a deployment.
